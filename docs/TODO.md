## ⚠️ REAL MULTIPLAYER CONVERGENCE (2026-07-08) — READ THIS FIRST

**The core problem (why the user is furious, and rightly so).** The game was
developed and tuned in **editor + G** ("in-process playtest"). Real multiplayer
(`serve.bat` / `join.bat` / `serve_and_play.bat`, i.e. `--server` / `--client` /
`--host`) uses a **completely separate, parallel level loader** that was written
long ago as a skeleton and **never run end-to-end until 2026-07-08**. So every
feature the user built over months in editor+G was simply *absent* from the real
game. It is NOT that fixes were undone — it's that this second path started at
~10% and each session the user hits another missing piece. This is convergence
work with a clear end, **not a rewrite.**

**The two loaders (memorise this):**
- **editor+G** → `server::level::reload_kenney_playtest` (fires on
  `KenneyPlaytestGeneration` bumps from client editor systems). Spawns the FULL
  level: floor cells + piece colliders + door seals + nav + enemies/NPCs. Layout
  source = user's hand-saved `userinput/maps/kenney_layout.json`.
- **real game** → `server::level::spawn_kenney_layout_colliders` (PostStartup) +
  `server::map_stream` hub streaming. Layout source = the **pool**
  (`userinput/maps/pool/*.json`, generated by `tools/build_map_pool.py`), mounted
  as `MountedMap` at world offsets with faction-chain streaming.
- **RULE: any gameplay/visual feature must be wired into BOTH.** Prefer calling
  the SAME spawn fn from both paths (that's how the fixes below were done).

### FIXED in the real-game path (2026-07-08 sessions)
1. **Dedicated `--server` ran the wrong game.** `run_server()` never enabled pool
   mode. Also, headless `--server` has no `AssetServer`/render app, so it could
   not load GLBs at all → wrote `server::headless_gltf` (raw `gltf` crate parse,
   no GPU) that bakes the same trimesh colliders. `HeadlessServer` marker gates
   the phantom listen-server player. serve.bat / playtest doc corrected.
2. **Floor fall-through.** `spawn_instance_pieces` was skipping `template-floor`
   (expecting cuboid cells) while `kenney_mesh_covers_cell` assumed the trimesh
   existed → no collider at all. Now bakes the flush trimesh like the editor path.
3. **Legacy hub hijack / wrong menu on spawn.** `check_extraction` (old sewer
   game) fired on any `y < -1.5` with no XZ gate → dumped players into the OLD
   `hub_medbay` stretch-graph menu. Guarded it with `PoolIndex::…is_some()`; added
   `check_pool_extraction` using the active map's real `extraction_xz`.
4. **Doors did nothing.** `spawn_hidden_door_seals` (gate-door open/close collider)
   was editor-only → added `spawn_instance_door_seals`, wired into
   `spawn_stream_geometries`.
5. **No enemies / NPCs.** The streaming loader never called the agent/nav spawner.
   Added `level::spawn_stream_gameplay` (nav `EnemyNav::from_layout` +
   `spawn_agents_from_layout`), called from bootstrap AND `stream_hub_commit`
   (which now also despawns old `Enemy`/`Npc`). Pool maps DO carry
   enemy_spawns/npc_spawns/nav; active map offset is ZERO so world==local coords.
   Verified: 5 enemies + 5 NPCs + A* nav on multiple maps.
6. **Wrong colour palette.** Client `build_modules` was hardcoded to the grey
   space atlas for every non-laser/non-ceiling piece → routed it through the same
   `kenney_material_slot` the editor uses. Industrial `template-wall` → weathered
   steel (`SpaceIndustrial`, MetalPlates013 PBR) per user request.
7. **Lighting.** Real games were using the empty-editor-canvas "dev preview" flood
   (two ANGLED directionals → bright glint streak across every ceiling), then
   briefly too-dark. Now `RealGameRun` gets the editor+G look: ambient 3000 + one
   **straight-down** overhead sun (34000, no shadow) — no angled glint. (Tunable in
   `darkness.rs` `REAL_GAME_AMBIENT_BRIGHTNESS` / `REAL_GAME_SUN_ILLUMINANCE`.)
8. **Synth deck: props/doors sunk INTO the 1.2 m raised floor** instead of on top.
   ROOT CAUSE (this was NOT a pool-generator bug — earlier guess was wrong): 
   `MountedMap::piece_translation` (shared, used by BOTH streaming colliders and
   client visuals) computed Y as `p.floor * MOD_H`, **discarding the per-piece
   `p.y`**. Synth deck props carry explicit `y = 1.2 / 2.4`; they were forced to
   floor level. Editor path always used `p.world_y()`. Fixed `piece_translation`
   to use `p.world_y() + offset.y`. This one fix covers doors, rails, computers,
   containers — everything on the synth deck.
9. **`--start-map <id|random>`** CLI added (`main.rs` → `map_pool::
   set_start_map_override`) to pick/randomise the starting pool map. Two-process
   server+client must pass the SAME explicit id (not `random`).
